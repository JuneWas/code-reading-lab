# 設計判断

| 判断日 | 採用した判断 | 採用理由 | 見送った代替案 |
| --- | --- | --- | --- |
| 2026-11-22 | Vue 3・JavaScript・Vite をリポジトリ直下で使う | 小さな画面から始め、学習対象でもある JavaScript と Vue.js で段階的に拡張できる。 | TypeScript の導入、フロントエンド専用サブディレクトリの作成 |
| 2026-11-22 | Phase 0 の画面を CSS と Vue の標準機能で構成する | トップ画面に必要な表示を少ない依存関係で実現できる。追加ライブラリの要件は各機能の実装時に判断できる。 | UI ライブラリやコードエディタの先行導入 |
| 2026-11-22 | MVP を静的フロントエンドとして設計し、進捗はブラウザ内に保存する | サーバーの運用を伴わず、読解と修正の学習体験を段階的に作れる。 | 認証、データベース、サーバー側の Java 実行を備える構成 |
| 2026-11-22 | Git 管理下の Markdown に仕様・設計・進捗を記録する | コードと同じ変更履歴から開発状況を確認でき、新しいチャットでも作業を再開できる。 | チャット履歴や外部の作業メモを主な引き継ぎ元にする運用 |
| 2026-11-22 | 問題データを JavaScript の静的配列で管理し、`type` で共通項目と回答用の項目を切り分ける | 少数の問題を GitHub でレビューでき、ライティング追加時に読解専用項目を埋める必要がなくなる。 | 問題配信用の API・データベース、全タイプに共通の回答項目を必須にする形式 |
| 2026-11-22 | 問題 ID と問題内の選択肢 ID を固定し、読解の正解を選択肢 ID で参照する | 問題名や表示文、表示順を変更しても、進捗や正解の参照先を維持できる。 | タイトル、表示文、配列のインデックスによる参照 |
| 2026-11-22 | ソースコードを MVP から `files` 配列に格納し、当面は 1 件とする | ファイル名と本文を対応付けられ、複数ファイル化で既存データを移行せずに済む。 | 本文のみの文字列を格納し、複数ファイル対応時に形式を移行する方法 |
